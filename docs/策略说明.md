## 三、★ 一个必须先想清楚的坑：`sz` 是「张」，不是 U

OKX 永续的下单量 `sz` 单位是**合约张数**：

```
每张名义价值 = ctVal × ctMult × 价格
```

| 合约 | ctVal | 一张大概值 |
|---|---|---|
| BTC-USDT-SWAP | 0.01 | ≈ 600 U |
| ETH-USDT-SWAP | 0.1 | ≈ 300 U |
| SOL-USDT-SWAP | 1 | ≈ 150 U |
| 小币种 | 1 | 常常 < 1 U |

所以 `margin_usdt: 1.0` + `leverage: 20` = **20U 名义**，只能买得起「每张 ≤ 20U」的合约。
BTC / ETH / SOL 这类会自动被跳过，日志里会写清楚：

```
名义 20U 买不起 0.1 张（每张名义 300.00U，至少要 1.50U 保证金）；调大 entry.margin_usdt，或把 margin_policy 改成 "min_one"
```

两个选择：

| `margin_policy` | 行为 |
|---|---|
| `fixed`（默认） | 严格按 `margin_usdt` 来，买不起就跳过 —— 忠于原口径，只做小币种 |
| `min_one` | 自动把保证金放大到刚好买 1 张，但不超过 `max_margin_usdt` —— 大小币种都能做 |

## 四、8 因子口径（逐位照抄文案 §5）

| bit | 因子 | 命中条件 |
|---|---|---|
| 0 | 势能 | `(close - SMA200) / ATRP14 < -1.0` |
| 1 | 摩擦 | `ATRP14 / ATRP96 > 0.5` |
| 2 | 动能 | `0.5 × vr × vel² × sign(vel) < 0`，`vel=(close/close[i-6]-1)×100`，`vr=vol/SMA(vol,48)` |
| 3 | RSI | `RSI14 < 30`（Wilder） |
| 4 | 布林 | `close < SMA20 - 2σ`（**总体方差 ÷20**，不是 19） |
| 5 | MACD | `hist[i] > hist[i-1] > hist[i-2]`，`DEA` 周期 **60**（不是 9） |
| 6 | TD9 | `close[i] < close[i-4]` 连续 ≥ 7 |
| 7 | 放量 | `vol > 1.5 × SMA(vol,20)` |

`score = popcount(mask)`，全合约阈值 **6**（BTC/ETH 用 7）。

## 六、运行流程

```
每轮 Run(bar)
  ├─ 连接 OKX（自动挑 www / aws / okx.com，并对时）
  ├─ ① 出场检查（每轮都做，与周期无关）
  │     止盈 +1% / 布林上轨 / 超时 6 小时 / 硬止损（止损默认关）
  ├─ ② 若该周期在 bars_enabled 里 → 扫描
  │     合约列表(缓存6h) → 行情粗筛 top80 → 并发算 8 因子
  │     → score ≥ 阈值 → 记库 → 闸门 §7.6 → 下单 → AI 点评
  ├─ ③ 权益快照
  ├─ ④ 运行日志落库
  └─ ⑤ 每 20 轮滚动清理（kline 每合约留 5000 根 / runlog 7 天 / equity 90 天）
```

## 七、上线顺序

1. `dry_run: true` + `simulated: true` → 跑 30 分钟，看日志里"候选 / 实算 / 信号"数字是否合理
2. 挑 1 条信号**手算核对**指标（这一步不做，后面全是假数据）
3. `dry_run: false`（还是模拟盘）→ 真下单，观察 3 天
4. 换成实盘 Key，`simulated: false`，单笔先 20~50U 试水
5. 建议给 `exit.stop_loss_pct` 开个 8~10 —— 合约会被爆仓，2G 小资金经不起一次插针
