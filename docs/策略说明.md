## 一、一句话概括

**全市场 480 个 USDT 永续 → 准入筛掉不该买的 → 每个周期各扫一遍 →
8 个共振指标全中才买 → 止盈 +1% / 布林上轨 / 超时 6 小时出场；
加仓条件与买入完全相同，补原保证金 1/3，次数不限。**

## 二、四个周期

| 周期 | 状态 | 说明 |
|---|---|---|
| `1m` `3m` `5m` `15m` | **在册** | `model.EnabledBars` —— 前端选项卡、回补、信号回算、K 线清理**四处共用这一份名单** |
| `1H` `4H` | 下线 | 不在名单里，上面四条路径会一起拒绝 |

**四个周期都参与开仓**。每 60 秒扫一轮，四个周期依次扫；但**账户余额、持仓、出场巡检、
加仓判定只在最外层做一次**（它们与周期无关，各做 4 遍纯属白烧 300~400ms 网络往返）。

★ 跨周期必须共享「本轮已开仓集合」，否则同一个合约会被四个周期各开一次仓。

## 三、合约准入（`inst.tradeable`）

按顺序执行，先命中先出局，结论写回 `inst.tradeable` / `inst.exclude_reason`。

| # | 规则 | 阈值 | 排除码 |
|---|---|---|---|
| 1 | 不买美股 / ETF / 商品 | `instCategory != 1` | `stock_etf` `commodity` `category` |
| 2 | 不买刚上线的 | 上市 < 30 天 | `new_listing` |
| 3 | 不买要下线的 | OKX 公告中心下线名单（24h 缓存） | `delisting` |
| 4 | 24h 成交额下限 | ≥ 100 万 USDT | `low_volume` |
| 5 | 最小一手买得起 | `minSz × ctVal × ctMult × 价 ÷ 杠杆 ≤ 1U` | `notional` |

实测 **480 → 170 个可交易**。第 5 条的上限是 `max_order_margin_usdt`（当前 **1.0**）。

## 四、★ `sz` 是「张」，不是 U ★

OKX 永续的下单量 `sz` 单位是**合约张数**，每张名义价值 = `ctVal × ctMult × 价格`。

| 合约 | ctVal | 一张大概值 |
|---|---|---|
| BTC-USDT-SWAP | 0.01 | ≈ 600 U |
| ETH-USDT-SWAP | 0.1 | ≈ 300 U |
| SOL-USDT-SWAP | 1 | ≈ 150 U |
| 小币种 | 1 | 常常 < 1 U |

所以「单笔 0.01U」在物理上不是总能成立：

* `0.01U × 20x = 0.2U` 名义价值 → 只能买「每张 ≤ 0.2U」的合约；
* 实测 170 个可交易合约里，**只有 32 个**能真按 0.01U 成交最小一手；
* 其余 138 个的最小一手保证金落在 **0.01 ~ 0.73U** 之间。

| `margin_policy` | 行为 |
|---|---|
| `fixed` | 严格按 `margin_usdt` 来，买不起就跳过 —— 只做小币种 |
| **`min_one`（当前）** | 目标 `margin_usdt`，买不起就放大到刚好买 1 张，**硬顶 `max_margin_usdt`** |

日志里会写清楚实际用了多少：
`名义 0.2U 买不起 0.1 张（每张名义 300.00U，至少要 1.50U 保证金）；min_one → 放大到 1.00U`

## 五、资金口径

```
每笔目标保证金   0.01 USDT
杠杆             20x（effLever：实际按 min(策略杠杆, 合约上限) 收敛，有 4 个合约只有 10x）
保证金模式       全仓 cross，pos_side=net（只做多）
单笔硬上限       1 USDT
准入上限         最小一手保证金 ≤ 1 USDT
持仓数           不限（max_concurrent_positions: 0 = 不限）
当日开仓数       不限（daily_max_entries: 0 = 不限）
冷却             cooldown_bars: 6
```

> ★ **同一个量被两条路算过时，口径必须一致** ★
> 准入过滤用 `effLever(合约上限, 策略杠杆)`，下单/算张数也必须用同一个 ——
> 曾经准入用 20x 判定、下单用裸 20x，导致 10x 上限的合约「准入放行、下单被 OKX 拒（59102）」，
> 那批合约**永远买不进来**。

## 六、8 因子口径

| bit | 因子 | 命中条件 |
|---|---|---|
| 0 | 势能 | `(close - SMA200) / ATRP14 < -1.0` |
| 1 | 摩擦 | `ATRP14 / ATRP96 > 0.5` |
| 2 | 动能 | `0.5 × vr × vel² × sign(vel) < 0`，`vel=(close/close[i-6]-1)×100`，`vr=vol/SMA(vol,48)` |
| 3 | RSI | `RSI14 < 30`（Wilder） |
| 4 | 布林 | `close < SMA20 - 2σ`（**总体方差 ÷20**，不是 19） |
| 5 | MACD | `hist[i] > hist[i-1] > hist[i-2]`，`DEA` 周期 **60**（不是 9） |
| 6 | TD9 | `close[i] < close[i-4]` 连续 ≥ 7 |
| 7 | 放量 | `vol > 1.5 × SMA(vol,20)` |

`score = popcount(mask)`。

**阈值 `score_threshold: 8` = 八个必须全中。** `score_threshold_map` 为空（不再给 BTC/ETH 单独放宽）。

> ⚠ **实测风险，务必知悉**：最近 30 天的 2329 条信号里，score 分布是
> **6 → 2168 条、7 → 161 条、8 → 0 条**。
> 也就是说阈值 8 极可能**长期一单都不下**。要真实下单，先把阈值降到 7。
> 这个数字是实测的，不是估计。

## 七、买入 / 加仓 / 出场

### 买入（每 60 秒，四个周期各扫一遍）

```
合约列表(缓存6h) → 行情粗筛 top80(按成交额) → 并发算 8 因子
  → score ≥ 阈值 → 记库 → 过闸门 → 下单
```

闸门顺序：`tradeable` → 冷却 → 当日笔数（0=不限）→ 持仓数（0=不限）→
可用余额（`min_available_usdt`）→ 算张数与保证金。

### 加仓 —— **条件与买入完全相同**

| 项 | 口径 |
|---|---|
| 触发 | **8 因子共振全中**（与买入同一个 `LatestSignal`，不是另取窗口） |
| 判定周期 | `rise_bar: "auto"` = **按该仓位自己的周期**（1m 开的仓按 1m 判、15m 开的仓按 15m 判） |
| 补仓额 | 原保证金的 **1/3**（`ratio: 0.3333`） |
| 次数 | **不限**（`max_times: 0`） |
| 间隔 | `min_gap_bars`（按周期根数换算） |
| 时效 | 信号必须晚于开仓时间 |

> ★ **「与买入一致」必须在代码上是同一个函数 ★**
> 加仓走 `LatestSignal()`（= `loadCandles` + `IndexOfLastClosed` + `ComputeSignal`），
> 与买入扫描、出场布林上轨共用。自己另取窗口会让递归指标（ATR/RSI/EMA/TD9）的
> **种子位置不同 → 值不同 → 「一致」变假**。

### 出场（三条，每 3 秒巡检）

| 条件 | 参数 |
|---|---|
| 止盈 | `take_profit_pct: 1.0`（浮盈 ≥ +1% 立刻市价平） |
| 布林上轨 | `boll_upper_exit: true`（收盘价 > SMA20 + 2σ） |
| 超时 | `max_hold_minutes: 360`（6 小时） |
| 止损 | **关闭**（`stop_loss_pct: 0`） |

## 九、上线顺序

1. `dry_run: true` + `simulated: true` → 跑 30 分钟，看日志里「候选 / 实算 / 信号」是否合理
2. 挑 1 条信号**手算核对**指标（这一步不做，后面全是假数据）
3. **确认 `score_threshold`**：想真出单就得从 8 降到 7（见 §六 实测分布）
4. `dry_run: false`（还是模拟盘）→ 真下单，观察 3 天
5. 换成实盘 Key，`simulated: false`
6. 建议给 `exit.stop_loss_pct` 开个值 —— 合约会被爆仓，小资金经不起一次插针
