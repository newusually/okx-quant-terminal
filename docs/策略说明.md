## 一、一句话概括

**全市场 480 个 USDT 永续 → 准入筛掉不该买的（品类不限）→ 每个周期各扫一遍 →
`Score ≥ 3` 且触发那根 K 线涨跌幅 < -0.7%（严格小于，必须真跌）才买 → 出场三条：**止盈 +0.35%** / **止损 -300%（到不了）** / **超时 24 小时**（布林上轨已关闭）；
加仓 = **纯价格条件**（收盘价比买入价低超 1% 且该根涨 > 1%），补原保证金 1/3，次数不限。**

## 二、三个周期

| 周期 | 状态 | 说明 |
|---|---|---|
| `3m` `5m` `15m` | **在册** | `model.EnabledBars` —— 前端选项卡、回补、信号回算、K 线清理**四处共用这一份名单** |
| `1m` | **四期下线** | 用户口径「取消 1 分钟买入条件和买入信号和选项卡和 K 线图」。K 线已整段删除（251 万行） |
| `1H` `4H` | 下线 | 不在名单里，上面四条路径会一起拒绝 |

**三个周期都参与开仓**。每 60 秒扫一轮，三个周期依次扫；但**账户余额、持仓、出场巡检、
加仓判定只在最外层做一次**（它们与周期无关，各做 4 遍纯属白烧 300~400ms 网络往返）。

★ 跨周期必须共享「本轮已开仓集合」，否则同一个合约会被三个周期各开一次仓。

## 四、★ `sz` 是「张」，不是 U ★

OKX 永续的下单量 `sz` 单位是**合约张数**，每张名义价值 = `ctVal × ctMult × 价格`。

| 合约 | ctVal | 一张大概值 |
|---|---|---|
| BTC-USDT-SWAP | 0.01 | ≈ 600 U |
| ETH-USDT-SWAP | 0.1 | ≈ 300 U |
| SOL-USDT-SWAP | 1 | ≈ 150 U |
| 小币种 | 1 | 常常 < 1 U |

所以「单笔 0.1U」不是天然成立的，只是**在当前这 239 个合约上都成立**：

* `0.1U × 20x = 2U` 名义价值 → 只能买「每张 ≤ 2U」的合约；
* 实测 239 个可交易合约的最小一手保证金落在 **0.01 ~ 0.73U**，**全部 ≤ 0.1U**；
* 也就是说当前**没有一个合约会被 `min_one` 放大**（三期由 0.01U 调到 0.1U 的收益就是这个）。

| `margin_policy` | 行为 |
|---|---|
| `fixed` | 严格按 `margin_usdt` 来，买不起就跳过 —— 只做小币种 |
| **`min_one`（当前）** | 目标 `margin_usdt`，买不起就放大到刚好买 1 张，**硬顶 `max_margin_usdt`** |

日志里会写清楚实际用了多少：
`名义 0.2U 买不起 0.1 张（每张名义 300.00U，至少要 1.50U 保证金）；min_one → 放大到 1.00U`

## 五、资金口径

```
每笔目标保证金   0.1 USDT          ← 2026-10-02 三期由 0.01U 上调
杠杆             20x（effLever：实际按 min(策略杠杆, 合约上限) 收敛，有 4 个合约只有 10x）
保证金模式       全仓 cross，pos_side=net（只做多）
单笔硬上限       1 USDT
准入上限         最小一手保证金 ≤ 1 USDT（品类不限）
持仓数           上限 30（max_concurrent_positions: 30 = 达到即不再开新仓；0 = 不限）
当日开仓数       不限（daily_max_entries: 0 = 不限）
冷却             已取消（cooldown_bars: 0）
```

> ★ **十期（2026-10-02）：冷却下线，把关交给「持仓数量」** ★
>
> 用户原话：「冷却条件全部删除  改成数量 就是持仓数量 … 持仓数量要求 <30 就行」。
>
> | | 九期 | 十期 |
> |---|---|---|
> | `cooldown_bars` | 30（同合约两次开仓至少隔 30 根） | **0（取消）** |
> | `max_concurrent_positions` | 0（不限） | **30** |
> | 管理台控件 | 数值输入框 | **可选预设 / 可直接输入**（comboRow） |
>
> 实测换壳前后对比（同一批信号，来源 `/api/signals`）：
>
> | 跳过原因 | 换壳前 | 换壳后 |
> |---|---|---|
> | **冷却中（距上次开仓不足 N 根）** | **54 条** | **0 条** |
> | 该合约已持仓 | 97 | 17 |
> | 无 reason（已下单） | 125 | 7 |
>
> ⚠ **同时修掉一处判定漏洞**：冷却的判定原来内联在 `trader.go` 的 `runEntries`，
> 缺 `cd > 0` 守卫 —— `CooldownBars=0` 时若信号时间戳早于上次开仓（K 线回填 / 重扫），
> `s.Ts-last` 是负数，而 `负数 < 0` 恒为真，于是**冷却明明关掉却照拦**，
> 日志还写「距上次开仓不足 0 根」这种自相矛盾的话。
> 现已抽成 `service.cooldownBlocked()`，`cd <= 0` 是第一条放行条件，
> 由 `trader_gate_test.go` 逐条钉住。
> 这是同一个坑（「关闭值必须显式排除，不能靠算术巧合」）在本项目的**第四次**出现。

> ★ **同一个量被两条路算过时，口径必须一致** ★
> 准入过滤用 `effLever(合约上限, 策略杠杆)`，下单/算张数也必须用同一个 ——
> 曾经准入用 20x 判定、下单用裸 20x，导致 10x 上限的合约「准入放行、下单被 OKX 拒（59102）」，
> 那批合约**永远买不进来**。

## 六、8 因子口径

| bit | 因子 | 命中条件 |
|---|---|---|
| 0 | 势能 | `(close - SMA200) / ATRP14 < -1.0` |
| 1 | 摩擦 | `ATRP14 / ATRP96 > 0.5` |
| 2 | 动能 | `0.5 × vr × vel² × sign(vel) < 0`，`vel=(close/close[i-6]-1)×100`，`vr=vol/SMA(vol,48)` |
| 3 | RSI | `RSI14 < 30`（Wilder） |
| 4 | 布林 | `close < SMA20 - 2σ`（**总体方差 ÷20**，不是 19） |
| 5 | MACD | `hist[i] > hist[i-1] > hist[i-2]`，`DEA` 周期 **60**（不是 9） |
| 6 | TD9 | `close[i] < close[i-4]` 连续 ≥ 7 |
| 7 | 放量 | `vol > 1.5 × SMA(vol,20)` |

`score = popcount(mask)`，取值 **0 ~ 8 的整数**。

**阈值 `score_threshold: 3`（= 用户口径的「Score >= 3」）。** `score_threshold_map` 为空（不再给 BTC/ETH 单独放宽）。

> ★ 判定式始终是 `>= threshold`，配置值就是字面语义 ★
> `score` 是整数，判定处本来就是 `sig.Score >= threshold`，所以**配 3 就等于「≥ 3」**，
> 一个字都不用改（已用 `TestThresholdIsNonStrictGreaterOrEqual` 对 1~8 阈值 × 0~8 分数全枚举验证非严格语义）。
> ⚠ 历史沿革：三期口径是「8 个共振中 4 个及以上」，为了不改判定符号，当时把配置值写成 **4** 来表达「> 3」；
> 五期用户口径直接给到 **3**（`Score >= 3`），配置值与语义重新对齐。

### 额外条件：触发那根 K 线必须跌 < -0.7%（六期）

不是只看 `score`。**有信号的那根 K 线自己的涨跌幅**（`(收 − 开) ÷ 开 × 100`）还必须 **< -0.7%**（严格小于：跌恰好 0.70% 不算，必须跌更深）。

`min_bar_rise_pct` 从六期起是**带符号门槛**：

| 配置 | 含义 |
|---|---|
| `entry.min_bar_rise_pct: -0.7` | 触发那根必须真跌 < -0.7%（**当前**） |
| 写正数（如 `0.5`） | 旧语义：触发那根必须真涨 > 0.5% |
| 写 `0` | **显式关闭**该条件（只按 score 判） |
| 不写 | 默认 -0.7 |

> ★ 必须是指针（`*float64`）而不是 `float64` ★
> 值类型下「没写」和「写 0」都是零值，语义完全相反 —— 二期 `max_concurrent_positions` 正是栽在
> 「用户写的 0 被 `<= 0` 反压回默认值」。指针的 `nil` 才承载「没写」这一态。

> ★ 买入、加仓、信号入库三处共用同一个判据函数 ★
> `service.SignalQualified(sig, threshold, minRisePct)` —— 三处各写一遍就迟早对不上
> （图上画了 🚀 而实盘不买，或反之）。`NaN` 用 `!(a > b)` 判为**不合格**（保守）。

> ⚠ **实测风险（已缓解）**：二期阈值 8 时，最近 30 天的 2329 条信号里 score 分布是
> **6 → 2168 条、7 → 161 条、8 → 0 条** —— 阈值 8 长期一单都下不出来。
> 三期改成 **4** 之后实时扫描**每周期能出 1~9 条信号**，当日实际产生 `open 310 / addon 45 / close 56` 笔。
> **★ 五期进一步放到 `3` 且涨幅门槛降到 `0.5%`** —— 命中面会更宽，实际出单量以运行日志为准。

## 七、买入 / 加仓 / 出场

### 买入（每 60 秒，三个周期各扫一遍）

```
合约列表(缓存6h) → 行情粗筛 top80(按成交额) → 并发算 8 因子
  → Score ≥ 阈值 且 触发那根涨跌幅过门槛（六期：< -0.7% 必须真跌）  → 记库 → 过闸门 → 下单
```

闸门顺序（`runEntries` 里的真实顺序）：

```
① 全局风控 globalRiskBlock
     连亏暂停 → 权益熔断 → 可用余额下限(min_available_usdt) → 当日亏损 → 总保证金占比
② 策略暂停（eng.paused）
③ 持仓数        max_concurrent_positions  ★ 十期：30
④ 该合约已持仓
⑤ 冷却          cooldown_bars             ★ 十期：0 = 已取消
⑥ 当日笔数      daily_max_entries
⑦ 合约信息缺失 / calcSize（张数 + 保证金口径）
⑧ 下单
```

> ★ 三个「关闭值」都必须在判定式里显式排除 ★
> `max_concurrent_positions` / `daily_max_entries` 的判定是先 `> 0` 再看有没有超；
> 冷却在十期补上了同样的 `> 0` 守卫（详见 §五 的说明）。
> 少写这个前置，0 就会变成「已达上限 0」或「不足 0 根」，**第一笔信号就被拦掉**。

### 只读板块 NQ 有**自己一套**买入信号口径（十三期，2026-10-02）

用户口径：「买入信号共振给我 NQ 单独算，只算共振 4+ 下跌情况买入」。

配置根级新增一块 `nq_signal`（只影响 `NQ-INDEX`，**全市场那套一个字都没动**）：

```jsonc
"nq_signal": {
  "enabled": true,          // false = 关闭，NQ 退回全市场通用口径
  "score_threshold": 4,     // 共振门槛 Score >= 4（全市场是 3）
  "max_rise_pct": 0         // 该根涨幅必须**严格小于**它；0 = 只要收阴
}
```

| | 全市场（加密永续） | NQ（纳斯达克100） |
|---|---|---|
| 共振门槛 | `Score >= 3` | `Score >= 4` |
| 涨跌幅条件 | `RisePct < -0.7`（跌幅要够大） | `RisePct < 0`（**只要收阴**） |
| 判定入口 | `service.SignalQualified` | `service.ReadonlySignalRule.Qualify`（内部仍调 `SignalQualified` 判分数/暖机，只换涨跌幅那一条） |
| 用途 | 记库 + 下单 | **仅记库/展示**，永不进下单链路 |

**为什么必须分开算（实测数据，不是拍脑袋）**：Dukascopy 真实数据 2026-09-03 一整天，
NQ 单根波动上限只有 ±0.35% ——

```
3m  300 根：最大 +0.275% / -0.184%，跌破 -0.7% 的 0 根
5m  288 根：最大 +0.258% / -0.219%，0 根
15m  96 根：最大 +0.343% / -0.202%，0 根
```

沿用全市场的 -0.7%，NQ 的信号数**恒等于 0**（不是"少"，是永远没有），
而且不报错、日志正常 —— 这种"配置写了却一辈子不触发"最难被发现。

> ⚠ `nq_signal.max_rise_pct` 的 **0 是"只要收阴"**，与 `entry.min_bar_rise_pct`
> 的带符号三态（0 = **关闭**该条件）**语义相反**。同一份配置里同一个 0 两种意思，
> 已由 `TestReadonlySignalRule_ZeroMeansDownNotOff` 钉住，别把它改成复用三态。

> ★ 口径变更必须作废历史 ★ 水位线（`signal_scan_state`）会把「已算区间」整段跳过，
> `signals` 又是 `UNIQUE(inst_id,bar,ts)` + `INSERT IGNORE` —— 两个机制叠加，
> **只改配置不清状态 = 新口径永远不作用到历史 K 线上**，且不报错。
> 所以口径描述当指纹存进 `meta.nq_signal_rule`，对不上就删旧信号 + 删水位线重算。

### 加仓 —— **八期双模式，十期用价格模式（2026-10-02）**

模式由 `addon.mode` 选，两套参数**不共用键**（切模式不丢参数、不互相污染）：

| 模式 | 触发条件 |
|---|---|
| `resonance`（八期默认） | `score` **严格大于** `score_threshold`（2）且该根涨幅 > `bar_rise_pct`（0.7%） |
| **`price`（十期在用）** | 收盘价 < 买入价 ×(1 − `drop_pct`% = **3%**) 且该根涨幅 > `price_rise_pct`（**0.3%**） |

| 项 | 口径 |
|---|---|
| 十期触发 | **跌 3% + 该根涨 0.3%**（`drop_pct: 3.0` / `price_rise_pct: 0.3`）—— 「跌到位置 + 反弹启动」，与 score 无关 |
| 判定周期 | `rise_bar: "auto"` = **按该仓位自己的周期**（3m 开的仓按 3m 判、15m 开的仓按 15m 判）；**该周期若已下线（如 1m 老仓）自动退回主周期** |
| 补仓额 | 原保证金的 **1/3**（`ratio: 0.3333`） |
| 次数 | **不限**（`max_times: 0`） |
| 间隔 | `min_gap_bars`（按周期根数换算） |
| 时效 | 信号必须晚于开仓时间 |

> ★ **触发条件七期起与买入分道 ★**
> 加仓仍走 `LatestSignal()`（= `loadCandles` + `IndexOfLastClosed` + `ComputeSignal`）
> 取同一根已收盘 K 线（买入也用它，保证「同一根」不各算各的），但判据改为纯价格条件
> `sig.Close < EntryPx×(1−drop_pct/100)` && `sig.RisePct > price_rise_pct`。
> 买入仍走 `SignalQualified`（score + 涨跌幅门槛）—— 两者已在七期解耦。
>
> ⚠ `price_rise_pct <= 0` 时才退回读 `bar_rise_pct`（兼容只写了 bar_rise_pct 的老配置）；
> 十期两个键都是独立的正值，所以走的是 `price_rise_pct`。
> 两套参数的键**刻意不共用** —— 共用会变成「切到价格模式顺手把共振模式的参数改了」。

### 出场（★ 七期起三条，每 3 秒巡检）

| 条件 | 参数 | 状态 |
|---|---|---|
| 止盈 | `take_profit_pct: 0.35`（浮盈 ≥ +0.35% 立刻市价平，七期） | ★ **保留** —— 负责锁利 |
| 超时 | `max_hold_minutes: 1440`（**24 小时**，七期放宽） | ★ **保留** —— 兜底离场 |
| 止损 | `stop_loss_pct: 300`（浮亏 -300% 才平，物理上到不了） | ★ 七期：等效不设止损 |
| 布林上轨 | `boll_upper_exit: false` | **已关闭** |
| 止损 | `stop_loss_pct: 0` | **关闭**（不设止损） |

> ★ **为什么关掉布林上轨（不是审美问题，是 SNDK 那笔亏损的根因）★**
> 买入判据与上轨判据读的是**同一根已收盘 K 线**。那根既然涨了 >1%（入场硬条件），
> 它的 close 本来就有很大概率已经站在 SMA20+2σ 之上 ——
> 于是**开仓后下一轮 3 秒巡检立刻判「布林上轨」反手平掉**。
> 实测 `SNDK-USDT-SWAP`：23:58:22 开仓 → 23:58:37 平仓（相隔 **15 秒**），
> 开仓价 1744.30 → 平仓价 1741.40，**亏 0.17%**。赚的那几笔同样只有 0.06%~0.32%，
> 全是手续费级别的噪音。
>
> ★ **但止盈绝不能跟着一起关** ★ 实测 2026-10-02 00:40~00:55 的 9 笔纯超时平仓：
> 6 笔「未止盈」合计 **-0.0924U**、3 笔「到点自动平仓」+0.0767U ——
> 少了 +1% 锁利，超时那一刻的盈亏纯随机，净值反而是负的
> （其中 MU 超时平掉时已经 **+0.82%**，差一点就够止盈线）。
> 用户也是就此纠正的：「止盈 1% 不平仓有问题」。
>
> 用户口径（2026-10-02）：「不准平仓，不准爆仓，只能超时 1 小时自动平仓」——
> 「不准平仓」指的是**布林上轨那种乱平仓**，不是把止盈也关掉。

  `exclude_stock_etf` 默认 false、`min_bar_rise_pct` 带符号三态（不写 / 0 / 正负都原样生效）且默认 -0.7
