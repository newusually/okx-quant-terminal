# 界面现代化方案 —— Flex 风格工作台

> 十五期 · 方案稿（未动代码）
> 起因：用户要求「做 Flex，就是之前很早 Flex / Adobe Flash 的那个功能，能不能更漂亮、窗口移动等都好看点」，
> 并询问「最先进的是 Node.js WebView，帮我看哪里好」。

---

## 0. 一句话结论

**你要的「更好看」不是一个技术栈问题，而是一个动效与交互问题。**

- Flex 当年的高级感，100% 来自**面板可拖动 + 缓动曲线 + 状态过渡 + 换肤**这四件事，全部属于「布局 + 动画 + 状态管理」，与「渲染引擎是 Flash 还是浏览器」无关。
- 现代浏览器在这四件事上**全面超过 Flex**，另外还多两样 Flash 根本做不到的能力（真玻璃拟态 `backdrop-filter`、共享元素补间 `View Transitions`）。
- 「Node.js WebView」这句话需要修正：Node.js 是后端运行时，不是界面方案。桌面 WebView 壳是 **Electron / Tauri / Wails** 三家，其中 **Wails 才是 Go 同栈正解**，而 **Electron 在这台机器上必须出局**。

**建议：主线走「路线 A 前端现代化」，桌面壳（路线 B）作为可选加冕，Electron 不做。**

---

## 1. 先对齐三件事（认知纠偏）

### 1.1 Flex 的「漂亮」到底是什么

Adobe Flex（2006，MXML + ActionScript，跑在 Flash Player 上）当年的高级感来自五件事：

| # | Flex 能力 | 用户实际感知到的 |
|---|---|---|
| 1 | Panel 可拖动 / 停靠 / 折叠 | 「窗口能拖着走」 |
| 2 | 效果库 Move / Resize / Fade / Glow / Sequence | 「切换有动画」 |
| 3 | 弹性缓动 Bounce / Elastic / Back | 「松手会回弹，很活」 |
| 4 | States & Transitions | 「状态切换是连贯的」 |
| 5 | 运行时换肤 Skinning | 「能换皮肤」 |

**这五件事全是布局、动画、状态管理。** 唯一 Flash 独占的是矢量遮罩与滤镜合成（当年做炫酷片头用的），量化终端用不上。

### 1.2 Flex 概念 → 现代 Web 等价物（本方案核心表）

| Flex / Flash 概念 | 现代 Web 等价物 | 项目现状 |
|---|---|---|
| Panel 可拖动 | `position` + Pointer Events + `transform: translate3d` | **半有**（仅图例可拖，`okxLegendPos`） |
| Move / Resize Effect | **FLIP 技术** / Web Animations API | **无** |
| Easing（Bounce / Elastic / Back） | `cubic-bezier(.34,1.56,.64,1)` / `linear()` 弹簧曲线 | **无**（只有零散 `.12s` 线性） |
| States & Transitions | CSS 自定义属性过渡 + `@starting-style` | **无** |
| HDividedBox 拖拽分隔 | CSS `resize` + 动态 `grid-template-columns` | **无** |
| 运行时换肤 Skin | CSS 变量（`:root` 换值即换肤） | **变量已就位，未做切换** |
| Glow 发光 | 多层 `box-shadow` / `filter: drop-shadow` | 少量（连接点、画图选中） |
| Accordion / TabNavigator | 有 | 有（但切 tab 无过渡） |
| —— | **`backdrop-filter: blur()` 真玻璃拟态**（Flex 做不到） | 有 3 处 |
| —— | **View Transitions API 共享元素补间**（Flex 做不到） | 无 |

> ★ 最后两行是重点：现代浏览器有两样 Flash 时代**根本做不到**的东西。
> 所以「回到 Flash 那个年代的技术」这个方向是反的 —— 你手里的工具比 Flex 强一代。

### 1.3 「Node.js WebView」这句话要修一下

Node.js 本身不是界面方案，它是后端运行时。桌面 WebView 壳是这三个：

| | Electron | Tauri | **Wails** |
|---|---|---|---|
| 渲染内核 | Chromium **全量打包** | 系统 WebView2 | 系统 WebView2 |
| 后端语言 | Node.js | Rust | **Go** |
| 安装包体积 | 80–150 MB | 3–10 MB | 5–12 MB |
| 空闲内存 | 200–400 MB | 30–60 MB | 40–90 MB |
| 与项目硬口径（纯 Go / 禁 Node） | ❌ 冲突 | ⚠️ 引入 Rust | ✅ **同栈纯 Go** |
| 首次运行依赖 | 无 | WebView2 运行时 | WebView2 运行时 |

准确的表述是：**「系统 WebView + 原生后端」这一类方案（Tauri / Wails）比 Electron 更新、省 5~10 倍资源。**
而它的价值是**把网页打包成桌面 App**（本地文件、系统托盘、全局快捷键、无地址栏），**不是让界面变好看**。

> ★ 关键分岔：**你是远程浏览器访问，还是本机开窗口？**
> 如果是远程浏览器访问这台腾讯云机器，装任何桌面壳都没用 —— 双击打开的还是浏览器。
> 桌面壳只在「服务器本机点图标启动」时才有价值。

### 1.4 ★ 硬约束：这台机器只剩 621 MB 可用

实测（2026-10-02 17:58）：

```
总内存     4,031 MB
可用内存     621 MB
mysqld       512 MB   ← 已占用
```

Electron 空窗口就要 200 MB 起，**直接出局**。
Tauri / Wails 约 40–90 MB，理论可上，但必须留实测余量并在上线前跑压力测试。

## 2. 三条路线对比

| 维度 | 路线 A：前端现代化 | 路线 B：Wails 桌面壳 | 路线 C：Electron |
|---|---|---|---|
| 界面变好看 | ✅ **提升最大** | 与 A 相同（A 是前提） | 与 A 相同 |
| 额外内存 | **≈ 0**（浏览器已在跑） | +40 ~ 90 MB | +200 ~ 400 MB |
| 新增依赖 | **0** | Go 模块 + WebView2 运行时 | Node + Chromium |
| 改动范围 | 只动 `web/` | 新增 `cmd/desktop/` | 新增整个 Node 工程 |
| 静态资源免重编译 | ✅ **保持**（改 web/ 即生效） | ❌ 需重新打包 | ❌ 需重新打包 |
| 远程访问可用 | ✅ | ❌ 仅本机 | ❌ 仅本机 |
| 本机 4GB / 剩 621MB | ✅ | ⚠️ 需实测 | ❌ **劝退** |
| 与「纯 Go」硬口径 | ✅ 不冲突 | ✅ 同栈 | ❌ 冲突 |

**决策：先做路线 A 把漂亮度打满；路线 B 等 A 稳定后单独评估，且仅在你确实要本机开窗口时才做；路线 C 不考虑。**

理由：路线 A 的效果提升最大、代价最小、且**不影响你现有「改前端免重编译」的快速迭代优势** —— 这是你目前迭代速度的关键。

## 3. 路线 A 详细清单

分三档。P0 = 立刻能感觉到，P1 = 「窗口移动好看」的核心（你问的重点），P2 = 锦上添花。

### P0 · 立刻见效

1. **全局缓动令牌**（★ 性价比最高）
   定义一套时间与曲线变量，把现在零散的 `.12s` 全量替换：

   ```css
   :root{
     --dur-1: .16s;                                   /* 悬浮、按下 */
     --dur-2: .28s;                                   /* 面板移动、展开 */
     --dur-3: .45s;                                   /* 页面级过渡 */
     --ease-out:    cubic-bezier(.22, 1, .36, 1);     /* 干脆收尾 */
     --ease-spring: cubic-bezier(.34, 1.56, .64, 1);  /* 轻微过冲 = 「活」 */
   }
   ```

   同样的界面，曲线一换就「活」了。这是 Flex 弹性缓动的等价物。

2. **微交互**：按钮按下 `scale(.97)`；卡片悬浮 `translateY(-1px)`；切 tab 内容淡入 + 位移 8px。
3. **数字滚动**：顶栏权益 / 浮盈变化时做 0.3s 计数补间，并涨绿跌红闪一次（Flash Glow 的等价物）。
4. **信号入场脉冲**：K 线打新信号标记时 `scale(.4 → 1.25)` + 淡出 0.8s 脉冲（复用现有 `fx-pop` 雏形）。

### P1 · 「窗口移动好看」的核心

5. **浮动面板工作台**（★ 最像 Flex 的一条）
   三栏从写死的 flex 布局升级为**可拖动 / 可缩放 / 可折叠**。
   - 拖动中：`scale(1.008)` 微微抬起 + 阴影 `0 8px 24px` → `0 24px 64px` + `z-index` 提到顶层
   - 松手时：用 **FLIP** 播 0.28s 弹性曲线到位（不触发重排、60fps）
   - 位置与尺寸存 localStorage，刷新保持
6. **磁性吸附 + 对齐辅助线**
   拖动面板距其他面板 / 容器边缘 12px 内自动吸附，并显示 1px 高亮辅助线。
   **这是「专业感」的最大来源**，比阴影和模糊都管用。
7. **可拖拽分隔条**（`HDividedBox` 等价物）
   三栏之间加 6px 分隔条，拖动改宽度，双击复位，宽度存 localStorage。
8. **停靠 / 浮动双模式**：每个面板标题栏两个小按钮 —— 停靠回原位 / 浮到最上层。
9. **双击标题栏最大化**，再双击还原。

### P2 · 锦上添花

10. **View Transitions API**：切 tab、切合约时用 `document.startViewTransition()` 让浏览器自动做旧→新补间。切合约可以做到「K 线图不闪、只交叉淡入」。
11. **玻璃拟态升级**：顶栏 / 图例 / 弹窗统一 `backdrop-filter: blur(12px) saturate(1.4)` + 内描边 `inset 0 1px 0 rgba(255,255,255,.06)`，层次立刻上一个档。
12. **换肤**：CSS 变量已就位，加主题切换（暗金 / 暗蓝 / macOS 浅色）。你偏好的 macOS 浅色风格可以做成一个主题。
13. **滚动驱动动画**：表格滚动时表头阴影渐显（`animation-timeline: scroll()`）。
14. **最小化到底部 Dock**（macOS 风格）：最小化的面板缩成 Dock 图标，点击弹回。这是「好看」的天花板。

### 技术选型（路线 A 用什么实现）

- **继续原生 JS，零框架零构建。** `app.js` 已是 2677 行命令式代码，引入 React/Vue 等于推翻重来，收益不抵风险。
- 只写两个自研小工具：
  - **FLIP 助手**（约 30 行）—— 记录首末位置，反向 transform 后播放到 0
  - **Pointer 拖拽**（约 60 行）—— 统一鼠标 / 触摸，`setPointerCapture` 防丢事件
- **不引第三方拖拽库**（interact.js / gridstack 都 40KB+，且会跟 lightweight-charts 抢鼠标事件 —— 项目里已经踩过一次叠加层的坑）。

## 4. 路线 B（Wails 桌面壳）细节

如果确定要「本机开窗口」的体验：

- 新增 `cmd/desktop/main.go` + `wails.json`，前端指向现成的 `web/` 目录 —— **前端一行不用改**
- Go 侧只暴露两个绑定：启动 / 停止 Web 服务（复用现有 `internal/`）
- 产物：单个 `okxterminal.exe`，约 10 MB，双击即开，无地址栏
- 系统托盘：显示运行状态、一键启停引擎
- 全局快捷键：唤出 / 隐藏窗口

**风险与代价：**

1. WebView2 运行时需预装（Win11 自带；Windows Server 2022 需装 Evergreen Runtime，约 130MB 一次性）
2. 打包后 `web/` 变只读 —— **失去「改前端免重编译」这个现有优势**，这是最大的代价
3. 内存必须实测（目标 < 90MB），上线前做压力验证

## 5. 建议的落地顺序

| 步骤 | 内容 | 成本 | 效果 |
|---|---|---|---|
| 一 | P0 的 1 / 2 / 3：换缓动曲线 + 微交互 + 数字滚动 | 低（只改 `style.css` + 少量 `app.js`） | 立刻可见，刷新即生效 |
| 二 | P1 的 7 → 5：先拖拽分隔条，再浮动面板 | 中（后者需重组 `layout` 的 HTML） | 「窗口能拖」的核心体验 |
| 三 | P1 的 6 / 8 / 9：吸附、停靠、最大化 | 中 | 专业感 |
| 四 | P2 挑着做（建议先 10 和 11） | 低 | 精致度 |
| 五 | 路线 B 桌面壳（可选） | 中高 | 仅在需要本机 App 时 |

**桌面壳放在最后，且不做也不影响界面漂亮度。**

---

## 6. 需要拍板的三件事

1. **你是远程浏览器访问，还是本机开窗口？** → 决定要不要路线 B。
2. **「漂亮」你更想要哪一种？**
   - a) 深邃专业：暗金玻璃、微动效克制
   - b) 灵动炫技：弹性过冲、面板飞舞、底部 Dock
   - c) macOS 浅色：你之前偏好的风格，做成一个主题
3. **浮动面板要不要？** 它最像 Flex 那种「工作台」，但会改变现在的肌肉记忆（三栏固定 → 可自由摆放）。
