二、★ 判据统一：三处必须调同一个函数 ★

用户说「加仓与买入条件一致」。二期是「两边各写一遍相似代码」，三期把它收成一个函数： 

func SignalQualified(sig *Signal, threshold int, minRisePct float64) bool {
    if sig == nil || !sig.Ready      { return false }
    if threshold <= 0                 { return false }
    if sig.Score < threshold          { return false }
    if minRisePct > 0 && !(sig.RisePct > minRisePct) { return false }
    return true
}
调用点文件作用
买入扫描internal/service/scanner.go Scan()决定 res.Signals
加仓判定internal/service/addon.go decideAddon()纯函数、可单测
信号入库回算internal/service/sigbackfill.go决定 K 线图上的 🚀 与实盘一致
为什么写 4 而不是把符号改成 >：score = popcount(mask) 是 0~8 的整数， score > 3 与 score ≥ 4 逐值等价。 用 ≥ 4 可以让判定式始终保持 >= threshold 一种形式， 不给历史口径引入无意义的符号漂移。等价性由 TestThresholdFourIsExactlyScoreGreaterThanThree 对 0~8 全枚举钉住。

NaN 用 !(a > b) 判为不合格（保守）—— 开盘价为 0 或数据缺失时不冒进下单。

三、★ 指针三态：为什么 min_bar_rise_pct 必须是 *float64 ★

JSON 里写的语义
不写（nil）用默认 1.0
0显式关闭该条件（只按 score 判）
-1 等负数视为写错 → 回落 1.0
正数原值生效
值类型下「没写」和「写 0」都是零值，语义完全相反。 二期 max_concurrent_positions 正是栽在这上面 —— 用户写的 0 被 if X <= 0 { X = 默认 } 反压回默认值，配置「改了没用」。 指针的 nil 才承载「没写」这一态。 单测 TestMinBarRisePctThreeStates 覆盖 5 条。

四、★ 同根标记合并 ★

加仓 max_times=0 不限次数，1m 一根里可能补好几次 —— 原来图上会在一根 K 线下面叠一排箭头。 现在 aggregateEvents() 做三件事：

  • 分组键 = 「按该周期对齐后的秒级时间」+ kind。不同类型不互相合并（买入 / 加仓 / 平仓各一笔）。
  • 累加 sz / margin / pnl，count 记原始笔数；价格取时间最晚那一笔 （实现里显式比较 e.Ts >= c.Ts，而不是依赖调用方传入顺序 —— 这是被单测逼出来的修正）。
  • 收益率重算：多笔时 pnlPct = 合计盈亏 ÷ 合计保证金 × 100。 直接把各笔百分比相加没有意义（分母被重复计入）。

前端 tooltip 显示「合计 XU（N 笔）」，标记文本带 ×N 后缀。

八、本轮踩到并修掉的两个「静默失效」

① 同一个结构体有多个「构造入口」

cmd/okxweb/main.go 的 applyUniverseFilter 里手写了一份 service.UniversePolicy{...}，漏填 ExtraExclude —— 后果是手动黑名单 exclude_inst 只在下单扫描路径生效，写回 inst 表那条路径完全不看。

这与二期 Scan() 漏填 MarginPolicy（准入上限静默 1U→0.01U）是同一个坑的复现。 新字段加进结构体和构造器，绝不会自动进那个手写字面量，编译器也不报错（缺字段 = 零值）。 现已统一走唯一构造入口 service.UniversePolicyFromConfig(cfg)。

② 报数不全会误导判断

准入日志原来只打 4 类排除原因，202 个被「成交额」滤掉的完全不显示， 各项相加对不上总数（480 − 39 ≠ 239）。三期补上 成交额 -%d，账目才闭合。
