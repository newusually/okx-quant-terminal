## 一、需求原话与落地口径

> 「盘中有信号就实时发送邮箱要求买入 买入条件就是macd>0 and ref macd<0 refref macd<0
> 电脑端有一个专门接这个邮箱的软件可以实时接收邮件 有这个买入信号的就播放声音提醒」
> 随后更正：「不要客户端不要收邮件 就给我网页播放声音」

| 条目 | 口径 |
| --- | --- |
| 买入条件 | `val > 0 && prev < 0 && prev2 < 0`（当前根、前一根、前两根） |
| 数据源 | taker 买卖比上的 MACD(12,26,60)（taker_macd 预计算表，与副图同一条数据） |
| 提醒方式 | 网页 Web Audio 响铃 + 右上角横幅 + 标签页标题加 🔔，**无邮件、无客户端** |
| 只认收盘 | 正在走的那一根 MACD 会跳，只对 `ts+5m <= now` 的根出信号 |
| 三条口径 | dif / dea / hist 都落库；默认 **hist**（通达信里 MACD = 2×(DIF-DEA)），网页下拉可切 |

## 四、使用说明 / 已知边界

1. **第一次要点一下顶栏「🔕 信号提醒」**——浏览器规定没有用户手势就不许出声；开过一次后状态记住，下次打开自动带上（若浏览器仍拦，点一下页面任意位置即放行）。
2. 判定用哪条线：下拉「MACD柱 / DIF / DEA」，默认 MACD 柱。换口径不补播历史，只提醒切换之后的新信号。
3. **延迟**：信号根收盘后约 5~15 分钟提醒。瓶颈是 OKX priapi taker 接口本身出数就滞后 2 根左右（副图显示的也是同一份数据，图上看到的和提醒到的一致，不会互相打架）。
4. 页面必须开着才会响（网页方案的本质限制）；后台标签页会被浏览器节流，回到前台立刻补查，不会漏，只是晚。
5. 信号频率参考：MACD 柱口径 30 天 284 条 ≈ 9 条/天。
6. 回滚：`bin/okxweb.exe.bak_22g` 是上一版。
