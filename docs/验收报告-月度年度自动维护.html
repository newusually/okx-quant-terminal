三、月度任务六步 · 顺序决定生死

① 归档所有「还没归档过」的、早于本月的月份
   → archive/kline-15m-YYYY-MM.partNN.csv.gz + manifest-YYYY-MM.json
② 推送 GitHub 数据仓          ← ★ 必须在 ⑤ 之前 ★
③ 记录表清理（30 天）
④ 日志清理（30 天，DB + apache + 客户端）
⑤ 磁盘守卫（C 盘 < 10 GB → 只留当月；含 K 线侧 + 归档侧两个动作）
⑥ 清回收站

为什么 ① 是「补齐式」而不是「只导上个月」

⑤ 会把 K 线收缩到「只留当月」。如果某个早于当月的月份从来没见过归档文件， 那一刀下去就是永久损失 —— 库里删了、远端也没有。首次部署、停机几个月、上次导出失败 都会留下这种缺口月份。

实测撞上了：1 年回补正在把历史往里灌，-maint-dry 立刻报出 12 个缺口月份（2025-10 ~ 2026-08）。沿用旧逻辑， 这 12 个月里除 2026-09 之外全部会被无声删掉。

所以 ① 改为按 repo.KlineMonths()（库里实际存在的月份）逐个补缺， 判据是 manifest-<YYYY-MM>.json 是否存在（幂等，不会重复导出）。

② 失败时的门禁是精确的，不是「全停」

⑤ 的动作推送成功推送失败
删库里早于收缩点的 K 线执行 执行，但收缩点回退到第一个未归档月份
删本地 archive/ 里早于当月的归档执行 跳过 —— 本地是唯一副本

「收缩点回退」＝ 没归档的月份，一行都不删。正常情况下所有月份都已归档， 收缩点就是本月月初，与用户口径完全一致。

四、K 线删除走 DROP PARTITION，不是 DELETE

kline 是 RANGE COLUMNS(ts) 分区表，实测 20 个分区：

p_old, pw20260801, pw20260808, pw20260815, pw20260822, pw20260829,
pw20260905, pw20260912, pw20260919, pw20260926, pw20261003, pw20261010,
pw20261017, pw20261024, pw20261031, pw20261107, pw20261114, pw20261121,
pw20261128, pmax
方式代价结论
ALTER TABLE kline DROP PARTITION …毫秒级删数据文件，不产生 undo / redo / binlog采用
DELETE FROM kline WHERE ts < ?扫千万行，undo 日志会把 60 GB 磁盘写爆不可接受

选区必须保守：只有分区上界 ≤ cutoff 才整段 DROP（才代表分区里每一行都过期）； p_old / pmax 永不 DROP，残余交 PurgeKlineBefore（DELETE … LIMIT 5000 批间 20 ms）兜底。

只读验证（cutoff = 2026-10-01）：命中 8 个周分区 pw20260801…pw20260919；pw20260926 （上界覆盖到 10-03）被正确放过；cutoff = 2025-10-01 → 0 个。

五、调度：meta 表记「上次跑的月份」而不是定时器

本机 schtasks.exe 被安全策略拦（实测），且定时器不保证「月底那一刻进程活着」。

maintTickInterval = 30 * time.Minute   // 30 分钟比对一次
maintFirstDelay   = 90 * time.Second   // 启动 90 秒后才开始，别抢启动资源
metaLastMonthly   = "maint_last_monthly"
metaLastYearly    = "maint_last_yearly"

实测 meta 表内容：maint_last_monthly = 2026-10、maint_last_yearly = 2026。 已种子化 → 部署瞬间不会真清回收站，首次真实月度任务落在 11-01。

停机三天、重启二十次，这个月也只跑一次 —— 不重不漏。

六、本轮修掉的 5 个真缺陷（都不是理论问题）

#缺陷后果修法
1 推送失败被报成「[OK] 已推送」
git push … | findstr /v … 后判 errorlevel		 管道里是 findstr 的退出码；findstr /v 打出任意一行不含模式的内容就返回 0 → 脚本永远返回 0，删除门禁等于不存在 重定向到临时文件 → 立刻取 git 退出码 → 再过滤打印 → 删文件
2 tokens=2 取分支名取到空串 --abbrev-ref HEAD 只输出 1 个 token，实测 [tokens=2] -> []。一直靠 hardcode master 兜底蒙对，仓库改名 main 就静默推错 git symbolic-ref --short HEAD（delims= 整行取）→ 退 tokens=1 → 兜底
3 -maint-yearly 没有预演开关 写 bat 时把它当预演用 → 那一步就是真 DROP PARTITION 新增 -maint-yearly-dry
4 归档「只导上个月」+ 守卫会丢数据 缺口月份被无声删掉（实测 12 个月） 改「补齐式」+ 收缩点回退
5 文档承诺了、代码没做
注释写「推送失败只记警告」，代码确实只记		 然后照常删本地 archive/ —— 正是文档说要防住的事 归档侧删除仅 rep.Pushed 时执行

另修：Go 的 %-10s 按字节补齐会把中文标签补歪（「归档目录」12 字节 vs「待归档」9 字节，显示宽度都是 4 汉字）； 自动提交日期原样拼 %DATE% 会得到 auto(code): 2026/10/01 周四 12:58:26.78；call :pushone 的失败不传递。
